  4. 24-hour cancellation/reschedule window is evaluated in the wrong timezone

  const bookingDateTime = new Date(
    `${booking.bookingDate.toISOString().split('T')[0]}T${booking.bookingTime}`
  );
  .toISOString().split('T')[0] returns a UTC date, but bookingTime is stored as local time (e.g. "14:00"). Node.js parses the concatenated string as server-local time, not the coach's timezone. For a UTC+5:30
  deployment the boundary is evaluated ~5.5 hours off, allowing guests to cancel past the intended cutoff. Same pattern on both cancel (line 3141) and reschedule (line 3249).

  5. Race condition in cancel and reschedule — no database-level locking

  Both the guest cancel and coach cancel endpoints use a read-check-write pattern with no transaction or conditional WHERE status != 'cancelled':
  const booking = await dbStorage.getBookingById(...);    // read
  if (booking.status === 'cancelled') return 400;         // check
  await dbStorage.updateBooking(id, { status: 'cancelled' }); // write (no lock)
  A simultaneous guest and coach cancellation can both pass the check and produce duplicate cancellation events and emails. updateBooking in storage.ts has no conditional WHERE clause.

  https://github.com/Riplek/Riplek_v1/blob/098f04bbd17e1f31b8433211f22af6b935d8d64d/server/routes.ts#L3116-L3230

⏺ ★ Insight ───────────────────────────────────── 
  Issues 1 and 2 together form a token enumeration chain: issue 1 dumps all accessToken values unauthenticated; issue 2 lets any caller exchange an accessToken for a magicLinkToken. Even independently, each is
  exploitable — together they allow complete takeover of any guest account. Always filter DB row projections at the API boundary rather than returning raw ORM results.                                               
                                                                         
  Issue 5 (the race condition) is the classic check-then-act concurrency bug. The safest fix in Postgres/Drizzle is an atomic conditional update: UPDATE bookings SET status='cancelled' WHERE id=X AND status !=     
  'cancelled' RETURNING * — if the row count returned is 0, another actor beat you to it.
