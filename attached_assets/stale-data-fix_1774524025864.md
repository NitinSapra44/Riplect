# Stale Data & Real-Time Sync Fix

## Root Cause

`client/src/lib/queryClient.ts` has three settings that cause every stale-data issue in the app:

```ts
staleTime: Infinity,
refetchOnWindowFocus: false,
refetchInterval: false,
```

Multiple mutations also have incomplete or missing `invalidateQueries` calls, meaning even fixing the config alone won't resolve every issue.

---

## Sub-Problems

**1. Dashboard navigation shows stale data**
Moving between dashboard tabs and returning shows old data. Requires a hard refresh.
Affected: all dashboard tabs.

**2. Content doesn't appear on public profile after creation or edit**
Coach creates/edits events, sessions, blog posts, or products. Public profile still shows old version.
Affected: `events-management.tsx`, `combined-session-management.tsx`, `digital-products-management.tsx`, `blog-management.tsx`, `profile.tsx`.

**3. Availability changes don't reflect in the session booking flow**
Availability mutations only invalidate `/api/dashboard/availability` and `/api/dashboard/blocked-dates`. They never invalidate `/api/profiles/{username}/availability`, which the guest booking flow reads from.
Affected: `combined-session-management.tsx`, guest booking flow in `profile.tsx`.

**4. Guest portal shows stale data after coach actions**
Coach confirms a booking or changes session details. Guest portal still shows old status.
The dashboard query namespace (`/api/dashboard/*`) and guest portal namespace (`/api/guest/{accessToken}`) are fully siloed — coach-side mutations never invalidate guest-side cache.
Affected: `booking-detail.tsx`, `guest-portal.tsx`.

**5. Guest actions don't reflect on coach dashboard**
Guest cancels or reschedules. Coach dashboard still shows old status.
Guest portal mutations only invalidate their own token-based queries and cannot reach the coach's browser directly.
Affected: `guest-portal.tsx`, `booking-detail.tsx`.

**6. Location changes don't sync to public profile**
Location mutations only invalidate `/api/locations`. They never invalidate `/api/profiles/{username}`.
Affected: `locations-management.tsx`, `profile.tsx`.

**7. Tag changes don't sync to public profile**
Tag mutations in `profile-settings.tsx` invalidate dashboard tag queries but miss `/api/profiles`.
Affected: `profile-settings.tsx`, `profile.tsx`.

## Implementation

---

### Phase 1A — Fix QueryClient Defaults

**File:** `client/src/lib/queryClient.ts`

```ts
staleTime: 30 * 1000,
refetchOnWindowFocus: true,
refetchInterval: false,
retry: false,
```

Per-query overrides for specific cases:

```ts
// Booking messages
useQuery({ queryKey: [...], staleTime: 10 * 1000 })

// Payment settings, wallet
useQuery({ queryKey: [...], staleTime: 5 * 60 * 1000 })
```

### Phase 1B — Guest Portal Polling

**File:** `client/src/pages/guest-portal.tsx`

Add `refetchInterval` to the main guest portal query:

```ts
const { data, isLoading, error } = useQuery<GuestPortalData>({
  queryKey: [`/api/guest/${accessToken}`],
  enabled: !!accessToken,
  refetchOnWindowFocus: true,
  refetchInterval: 15 * 1000,
  refetchIntervalInBackground: false,
});
```

Add `refetchInterval` to the booking messages sub-query:

```ts
useQuery({
  queryKey: [`/api/guest/${accessToken}`, "bookings", bookingId, "messages"],
  refetchInterval: 10 * 1000,
  refetchOnWindowFocus: true,
})
```

### Phase 2 — Centralized Invalidation Utility

**Step A — Create `client/src/lib/cacheInvalidation.ts`**

```ts
import type { QueryClient } from "@tanstack/react-query";

export const invalidate = {

  profile: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/profile"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  sessions: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/sessions"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  availability: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/availability"] });
    qc.invalidateQueries({ queryKey: ["/api/dashboard/blocked-dates"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  events: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/events"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  products: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/products"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  blog: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/blog"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  locations: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/locations"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  tags: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/profile/tags"] });
    qc.invalidateQueries({ queryKey: ["/api/dashboard/profile/consolidated-tags"] });
    qc.invalidateQueries({ queryKey: ["/api/profiles"], exact: false });
  },

  bookings: (qc: QueryClient, guestAccessToken?: string) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/bookings"] });
    if (guestAccessToken) {
      qc.invalidateQueries({ queryKey: [`/api/guest/${guestAccessToken}`] });
    }
  },

  wallet: (qc: QueryClient) => {
    qc.invalidateQueries({ queryKey: ["/api/dashboard/wallet/summary"] });
    qc.invalidateQueries({ queryKey: ["/api/dashboard/wallet/transactions"] });
    qc.invalidateQueries({ queryKey: ["/api/dashboard/wallet/stripe-account"] });
  },

};
```

**Step B — Update every affected mutation's `onSuccess`**

Replace all hardcoded `queryClient.invalidateQueries(...)` calls across the components in the checklist above with the corresponding `invalidate.*` call. Example:

```ts
// Before
onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: ["/api/dashboard/availability"] });
}

// After
import { invalidate } from "@/lib/cacheInvalidation";
onSuccess: () => {
  invalidate.availability(queryClient);
}
```

Apply to all 11 rows in the missing invalidations checklist.

### Phase 3 — BroadcastChannel Cross-Tab Sync

**Step A — Create `client/src/lib/cacheChannel.ts`**

```ts
import type { QueryClient } from "@tanstack/react-query";
import { invalidate } from "./cacheInvalidation";

const CHANNEL_NAME = "riplek-cache-sync";

type CacheSyncEvent =
  | { type: "profile-updated" }
  | { type: "sessions-updated" }
  | { type: "availability-updated" }
  | { type: "events-updated" }
  | { type: "products-updated" }
  | { type: "blog-updated" }
  | { type: "locations-updated" }
  | { type: "tags-updated" }
  | { type: "bookings-updated" };

export function broadcast(event: CacheSyncEvent): void {
  try {
    const ch = new BroadcastChannel(CHANNEL_NAME);
    ch.postMessage(event);
    ch.close();
  } catch {}
}

export function listenForCacheSync(queryClient: QueryClient): () => void {
  try {
    const ch = new BroadcastChannel(CHANNEL_NAME);
    ch.onmessage = ({ data }: MessageEvent<CacheSyncEvent>) => {
      switch (data.type) {
        case "profile-updated":      invalidate.profile(queryClient); break;
        case "sessions-updated":     invalidate.sessions(queryClient); break;
        case "availability-updated": invalidate.availability(queryClient); break;
        case "events-updated":       invalidate.events(queryClient); break;
        case "products-updated":     invalidate.products(queryClient); break;
        case "blog-updated":         invalidate.blog(queryClient); break;
        case "locations-updated":    invalidate.locations(queryClient); break;
        case "tags-updated":         invalidate.tags(queryClient); break;
        case "bookings-updated":     invalidate.bookings(queryClient); break;
      }
    };
    return () => ch.close();
  } catch {
    return () => {};
  }
}
```

**Step B — Register in `client/src/App.tsx`**

```ts
import { useEffect } from "react";
import { listenForCacheSync } from "@/lib/cacheChannel";
import { queryClient } from "@/lib/queryClient";

useEffect(() => {
  const cleanup = listenForCacheSync(queryClient);
  return cleanup;
}, []);
```

**Step C — Add `broadcast()` alongside every `invalidate.*` call in mutations**

```ts
import { invalidate } from "@/lib/cacheInvalidation";
import { broadcast } from "@/lib/cacheChannel";

onSuccess: () => {
  invalidate.profile(queryClient);
  broadcast({ type: "profile-updated" });
}
```

Pair `broadcast()` with every `invalidate.*` call added in Phase 2.
